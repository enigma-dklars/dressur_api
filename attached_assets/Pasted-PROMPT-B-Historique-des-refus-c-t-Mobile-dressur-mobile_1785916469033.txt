PROMPT B — Historique des refus côté Mobile (dressur_mobile, branche dklars_pro)
Contexte :
Tu travailles sur le dépôt dressur_mobile (Flutter) cloné dans repos/dressur_mobile, branche dklars_pro.
C'est l'application mobile Dressur.
Le service "Promotion Affaire" permet de publier des annonces. Quand une promotion est refusée
par un admin, un motif est affiché à l'utilisateur. Actuellement un seul motif est affiché,
sans historique.
Une évolution vient d'être faite côté API : la réponse de l'API liste des promotions inclut
maintenant un champ motifsRefus (tableau d'objets avec motif:string et dateRefus:string).
Avant de toucher au code, lis ces fichiers :
- repos/dressur_mobile/lib/2_promo/liste_promo_affaire.dart (fichier complet)
- repos/dressur_mobile/lib/2_promo/edit_promo_affaire_produit_service.dart (fichier complet)
---
ÉTAPE 1 — Mettre à jour le modèle de données Promotion
Dans le fichier qui définit le modèle/classe Promotion utilisé par liste_promo_affaire.dart
(cherche une classe Promotion ou un fromJson dans liste_promo_affaire.dart ou dans un fichier
modèle séparé — lis le fichier pour trouver où la classe est définie) :
Ajoute un champ :
  List<MotifRefus> motifsRefus (initialisé à [] par défaut)
Crée une classe MotifRefus dans le même fichier (ou dans un nouveau fichier modèle si le projet
a une convention de fichiers modèles séparés) :
  class MotifRefus {
    final String motif;
    final String dateRefus;
    MotifRefus({required this.motif, required this.dateRefus});
    factory MotifRefus.fromJson(Map<String, dynamic> json) => MotifRefus(
      motif: json['motif'] ?? '',
      dateRefus: json['dateRefus'] ?? '',
    );
  }
Dans le fromJson de la classe Promotion, parse le champ motifsRefus :
  motifsRefus: (json['motifsRefus'] as List<dynamic>? ?? [])
      .map((e) => MotifRefus.fromJson(e as Map<String, dynamic>))
      .toList()
