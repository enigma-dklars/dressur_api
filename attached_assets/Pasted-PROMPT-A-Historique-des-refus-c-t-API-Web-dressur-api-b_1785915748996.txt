PROMPT A — Historique des refus côté API + Web (dressur_api, branche work_by_ai)
Contexte :
Tu travailles sur le dépôt dressur_api (Symfony PHP) cloné dans repos/dressur_api, branche work_by_ai.
C'est l'application web/API de Dressur.
Le service "Promotion Affaire" permet aux utilisateurs de publier des annonces.
Quand un admin refuse une promotion, il saisit un motif. Actuellement ce motif écrase le précédent
— il n'y a aucun historique.
Objectif : mettre en place un historique des motifs de refus, permettre l'édition du WhatsApp
après refus, et afficher cet historique à l'utilisateur (web) et à l'admin.
Avant de toucher au code, lis ces fichiers :
- repos/dressur_api/src/Entity/Promotion.php
- repos/dressur_api/src/Controller/Crud/CrudPromotionController.php (lignes 236-313)
- repos/dressur_api/src/Controller/API/PromotionController.php (lignes 608-705)
- repos/dressur_api/templates/private/listepromoaffaire.html.twig
- repos/dressur_api/templates/crud_promotion/ (liste les fichiers présents)
- repos/dressur_api/migrations/ (liste les fichiers pour trouver le dernier numéro de version)
---
ÉTAPE 1 — Créer l'entité PromotionMotifRefus
Crée le fichier : repos/dressur_api/src/Entity/PromotionMotifRefus.php
Cette entité représente un motif de refus historique pour une promotion.
Champs :
- id : int, auto-increment, clé primaire
- promotion : ManyToOne vers Promotion, nullable false, inversedBy "motifsRefus"
  (cascade persist n'est pas nécessaire ici)
- motif : text, nullable false — le texte du motif saisi par l'admin
- dateRefus : datetime, nullable false — date et heure du refus (setDateRefus dans le constructor)
Dans le constructor, initialise dateRefus à new \DateTime().
Suis le même style que les autres entités du projet (attributs PHP 8, Doctrine ORM attributes).
---
ÉTAPE 2 — Mettre à jour l'entité Promotion
Dans repos/dressur_api/src/Entity/Promotion.php, ajoute :
- Une relation OneToMany vers PromotionMotifRefus, mappedBy "promotion",
  champ nommé $motifsRefus, type ArrayCollection, initialisé dans le constructor,
  avec cascade persist et orphanRemoval false.
- Les méthodes getMotifsRefus(), addMotifRefus(PromotionMotifRefus $motif),
  removeMotifRefus(PromotionMotifRefus $motif).

ÉTAPE 4 — Modifier l'action de refus admin
Dans repos/dressur_api/src/Controller/Crud/CrudPromotionController.php,
dans la méthode refuser() (vers la ligne 286) :
Après avoir récupéré $motif depuis la requête et avant de persister :
1. Crée un nouvel objet PromotionMotifRefus
2. Appelle $motifRefus->setMotif($motif) — ou utilise le constructor si motif est passé dedans
3. Appelle $promotion->addMotifRefus($motifRefus)
4. Garde le setMotif($motif) sur $promotion pour compatibilité avec l'affichage rapide existant
5. Persiste et flush comme avant
NE PAS supprimer le setMotif($motif) sur $promotion — il est utilisé pour l'affichage rapide.
